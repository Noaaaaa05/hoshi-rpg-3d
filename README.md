# 星灯りの森 3D — Ver.0.2.4

ランタンひとつ、まだ知らない景色へ。iPhoneのSafariで遊べる、オリジナル3D探索アクションRPGです。Three.js / HTML / CSS / JavaScriptで制作しています。

開発はChatGPT WorkとClaude Codeのどちらからでも進められます。共通の [RPG自動化の手順](docs/RPG_AUTOMATION.md) と [進捗](docs/AUTOMATION_PROGRESS.md)、Claude Code向けの [手順](docs/CLAUDE_CODE.md) を参照してください。

## 遊び方

GitHub Pagesの公開設定後に **https://noaaaaa05.github.io/hoshi-rpg-3d/** をSafariで開き、iPhoneを横向きにして「森を歩きはじめる」を押します。

- 左のスティック：カメラの向きに合わせて360度移動。
- 画面右側の空いている場所をスワイプ：左右・上下に見回す。
- ジャンプ：タップ。スタミナを12消費します。
- ダッシュ：移動しながら長押し。スタミナを毎秒27消費します。
- 「Ⅱ」：一時停止、画質とカメラ感度の調整、開始地点へ戻る。
- PC：WASD / 矢印、Shiftでダッシュ、Spaceでジャンプ、右側をドラッグして視点変更、Escでメニュー。

攻撃ボタンはタップまたは長押し（連続攻撃）、回避ボタンはタップです。PCは **J：攻撃 / K：回避**。スティックを離した状態か前方向に倒した状態で回避すると、約0.72秒の前転をします。

8つの星灯りと、3つの風景「星詠みの石門」「星降りの古木」「旅人の灯り」を探してみてください。達成後も自由に探索できます。

## Ver.0.2.4：集落・持ち物・前転・RPGカタログ

- 野営地のそばに小さな集落（家3軒、屋台2つ）と、商人ルカ・衛兵セナ・村人ミオを追加しました。近づくと「話す」ボタンが出ます。ルカから薬草（20G）を買い、「持ち物」ボタンから使うとHPが30回復します。所持金と薬草は保存されます。
- 前転回避で、Meshyで生成した専用モーション `Hoshi_roll` を再生します。
- NPC・会話・クエスト・アイテム・技・エリアを `assets/rpg/catalog.json` に登録して追加できます。最初の例は見張り番ミナのクエストです。開始地点のそばのミナに話しかけ、北東の見張り台を訪ねて報告すると「森番の短剣」と「小径の三連撃」が手に入り、ミナを仲間にできます。PCでは **F：話す / L：技**。
- カタログへの追加だけのPRは、テスト合格後に自動でマージ・公開されます。手順は [docs/RPG_AUTOMATION.md](docs/RPG_AUTOMATION.md) を参照してください。

集落、NPC、敵、木や岩は、箱や球を組み合わせた仮の表示です。造形とテクスチャのある3Dモデルへ置き換える予定です（[対象の一覧](docs/AUTOMATION_PROGRESS.md)）。

## Ver.0.2.3：Meshyモーション自動化

GitHub Actionsの **Meshy motions** から、前転・左回避・右回避・後方回避・着地の計画と生成を実行できます。初期値はdry-runで、Meshyへのリクエストも課金もありません。新しい5モーションの有料生成は今回実行していません。

`MESHY_API_KEY` Secretと成功済みAPI Rigging IDを設定した後、対象・料金上限・明示的な有料同意を指定して実行します。骨格・速度・接地検査とブラウザテストを通過したアニメーション専用GLBだけをブランチ／PRへ反映し、mainの公開ゲームへは直接書き込みません。現在の主人公・マップ・戦闘・保存は維持します。

[必要な設定、iPhoneでの実行方法、料金・再リギング・品質検査の制約](docs/MESHY_AUTOMATION.md) を先に確認してください。

## Ver.0.2.2：待機・歩行・走行・剣攻撃

新しい `アニメモーション.glb`（66関節、10,112三角形）を導入しました。ゲームは同一内容の英字名 `hero_animated.glb` を読み込みます。`Idle_03` / `Walking` / `Running` / `Attack` を実際の名前で割り当て、約0.16秒で滑らかに切り替えます。剣は右手ボーンに取り付け、足元の高さを補正します。

既存の移動速度・カメラ・攻撃判定・ゲーム機能は維持しています。前転回避には追加の `Hoshi_roll` を再生します。ジャンプ・横回避・後方回避の表示にはIdleを使います。検査結果と調整方法は [`assets/models/ANIMATIONS.md`](assets/models/ANIMATIONS.md) を参照してください。

## Ver.0.2.1：Meshyオリジナル主人公（前バージョン）

前バージョンでは `assets/models/hero.glb` を元にした静的なオリジナル主人公を導入しました。原本は保持し、当時の通常表示には約264KB・14,998三角形の `hero-mobile.glb` を使用します。高さ1.9m、+Z正面、足元を地面に合わせています。元GLBには骨組み・アニメーション・テクスチャがないため、今回は静止ポーズと単色マテリアルです。移動・ジャンプ・ダッシュ・攻撃・回避・戦闘はそのまま機能します。

読み込み失敗・破損・時間切れでは簡易主人公で続行します。Idle / Walk / Run / Attack / Jump / Dodgeのクリップを将来指定できる構造です。検査結果と差し替え方法は [`assets/models/HERO.md`](assets/models/HERO.md) を参照してください。

## Ver.0.2の追加内容

- 通常攻撃：前方の範囲へ剣を振ります。攻撃モーション・斬撃・ダメージ数値を表示。1回の攻撃で同じ敵に何度もダメージは入りません。木や岩越しには届きません。
- 回避：STを22消費し、移動方向（入力なしでは正面）へ短く移動。約0.34秒の無敵時間と0.8秒の再使用待ちがあります。木や岩は通り抜けません。
- 森のスライム5体、小枝のゴブリン3体：巡回 → 発見・追跡 → 攻撃予告 → 攻撃 → 待機。赤い輪が敵の攻撃予告です。
- 敵の頭上と画面上部にHP表示。HPゼロで倒れる演出と討伐経験値。近くで倒した敵は、30秒以上経って主人公が元の配置場所から12m以上離れると復活します。ページ再読み込みでも復活します。
- 経験値・レベル・討伐数・HPを自動保存。レベルアップで最大HPが20、攻撃力が4上がり、HPが全回復します。上限Lv.50です。
- 初期値：HP100 / 攻撃力18、Lv.1→2に必要な経験値40。以降は必要経験値が25ずつ増加します。
- スライム：HP34 / 攻撃力8 / EXP18。ゴブリン：HP64 / 攻撃力12 / EXP30。
- 開始地点から半径8mは敵が入らない安全地帯。HPゼロでは育成を維持して開始地点へ戻ります。野営地でのHP回復も引き続き使えます。
- 攻撃・回避は従来のジャンプ・ダッシュの左隣に追加。スティック・カメラ・新ボタンのポインターを別々に追跡し、同時に操作できます。
- 敵の行動判断は20Hz、遠くの敵は休止。簡易モンスターは共有ジオメトリとインスタンシングで描画し、敵用の追加ライト・影・外部パッケージは使いません。
- `manifest.json` の `monsters.slime` / `monsters.goblin` で、戦闘ルールを維持したままGLBに差し替え可能。

**Ver.0.1の森林・地形・配置・ミニマップのソースと、通常移動・衝突・ジャンプ・ダッシュの物理処理は変更していません。** カメラの追従・スワイプ感度・描画品質設定もそのままです。戦闘は別の `js/combat.js` と `js/monsters.js` に追加しています。

旧セーブのキー `hoshi-rpg-3d:v0.1` を継続利用し、従来の位置・星灯り・発見場所・画質・感度を保持して、初回保存時にVer.0.2形式へ移行します。旧セーブにはLv.1 / EXP0を補完します。ブラウザのサイトデータを消す必要はありません。

## iPhoneだけで公開する

このリポジトリの`main`にソースを入れた後、GitHubのブラウザ画面で設定します。

1. Safariで **https://github.com/Noaaaaa05/hoshi-rpg-3d** を開きます。
2. リポジトリの **Settings → Pages** を開きます。表示されない場合はSafariのメニューから「デスクトップ用Webサイトを表示」を選ぶと操作しやすくなります。
3. **Build and deployment → Source** を **Deploy from a branch** にします。
4. **Branch** を **main**、フォルダを **/(root)** にして **Save**。
5. GitHubのPagesデプロイが終わったら、同じ画面に表示される公開URLを開きます。初回は数分かかることがあります。

ゲームのビルドやnpmの実行は不要です。Three.jsとGLBLoaderも同梱済みで、ゲーム起動時に外部CDNやAPIを呼び出しません。インターネットから最初にファイルを読み込む必要があります。オフライン保証やPWAキャッシュはありません。

## Ver.0.2のGitHubへの反映と復元

この更新は、まず作業ブランチで既存機能と戦闘のチェックを行い、その後 `main` へ反映します。Pagesを `main / (root)` から公開している場合、反映後はGitHubのPagesデプロイ完了を待ってSafariを再読み込みするだけです。スマホ側でのインストールやビルドは不要です。

手元の変更を送る場合：

```sh
git add .
git commit -m "Update to v0.2 combat and progression"
git push origin HEAD:main
```

Ver.0.1の基準コミットは `0fe4d51c3fbe74eceb15f3c1c14c48a358431137` です。`CHANGELOG.md` に差分と検証方法を記載しています。更新を戻す場合は履歴を強制上書きせず、PCまたはCodespacesから `git revert` でVer.0.2の変更を打ち消すコミットを作成してください。旧版は育成データを認識しないため、旧版へ戻す前にブラウザの保存データを控えてください。

## iPhoneだけで更新する

- HTML/CSS/JavaScript：GitHubのファイル画面の鉛筆ボタン → 編集 → **Commit changes**。`main`の変更がPagesへ反映されます。
- GLB：リポジトリ内の`assets/models`で **Add file → Upload files** から「ファイル」アプリ内のGLBをアップロード。続いて`manifest.json`を編集します。
- 編集が多い場合：GitHubのブラウザエディタ（リポジトリURLの`github.com`を`github.dev`に変更）を利用できます。GitHubアプリだけでは一部の編集機能を使えないため、Safariを使ってください。
- 自動チェック：**Actions → Game checks** で結果を確認できます。`workflow_dispatch`から再実行も可能です。
- 変更が見えない場合：Pagesのデプロイ完了を確認してSafariを再読み込みしてください。

保存データはSafariの`localStorage`です。同じ端末・同じサイトのURLで再開できます。別端末との同期はありません。プライベートブラウズやサイトデータ削除で記録が消える場合があります。保存が禁止された環境でも探索はできます。

## PC / Codespacesでの開発（任意）

Node.js 22以降で、リポジトリ直下から実行します。

```sh
npm run dev
# http://localhost:5173 を開く

npm run check
npm test
```

上記3コマンドは追加パッケージのインストール不要です。ブラウザの自動テストを実行する場合のみ以下が必要です。

```sh
npm ci
npx playwright install --with-deps chromium webkit
npm run test:browser
```

ルールテストでは、従来の移動・ジャンプ・衝突・スタミナの検証に加え、戦闘を加えても通常移動の計算結果が完全一致すること、攻撃の方向・距離・遮蔽物・多重ヒット防止、敵AI、回避、経験値、旧セーブの移行を検証します。ブラウザテストでは、ChromiumとWebKitの横画面で、起動、移動、ダッシュ、ジャンプ、カメラ、保存と復帰、GitHub Pagesと同じサブパスを確認します。Ver.0.2では実際の攻撃・被弾・討伐・レベルアップ・戦闘中のポーズ・育成保存も検証します。Chromiumでは従来の3点同時タッチと縦画面時の停止に加えて4点同時タッチ、568×320 / 844×390でボタンの重なりがないことを検証します。WebKitではGLBモンスターの差し替えと、読み込み失敗時の簡易モデルへのフォールバックを検証します。

**Linux上のWebKitテストはiPhone実機Safariの性能・発熱・ノッチ・ブラウザツールバーの保証にはなりません。** 推奨環境はiOS 16.4以降のSafari（WebGL2 / ES modules / import maps対応）です。端末が熱くなる場合や描画が重い場合はメニューで「軽量」を選んでください。GLBを追加した場合は実機で読み込みサイズと描画負荷を確認してください。

`?debug=1`付きで開くと、開発者ツールの`window.__HOSHI_DEBUG__`から位置、カメラ、描画数などを読み取れます。通常起動時には公開されません。
