## 実装した基盤と次の作業

| 対象 | 実装した範囲 | 次に必要な作業 |
| --- | --- | --- |
| A キャラクター | 低ポリゴンモデル、GLB登録、NPC・敵・仲間の配置、アセット検査 | 新規Meshyキャラの生成・自動リグを、承認済みタスクの取得からつなぐ |
| B モーション | 埋め込みクリップと同一骨格GLBの登録、区間・速度・ループ・ブレンド、既存前転の再現 | 任意BVH/FBXの骨格マッピング、主人公の全動作と新技専用クリップの切り替え |
| C 操作と戦闘 | 既存の移動と回避、データ定義の敵、仲間追従、複数命中の剣技 | 仲間の戦闘AI、独立した技のモーションや演出 |
| D マップ | 既存地形にエリア、建物や小物、配置、衝突、移動先を登録 | 独立した街やダンジョンの地形生成、複数シーンの読み込み |
| E ストーリー | 会話分岐、前提クエスト、訪問・討伐、報酬と保存 | 本編の章、複数段階のシナリオ、演出イベント |
| F UIと持ち物 | 会話、クエスト表示、報酬、装備、回復品、技の操作 | 既存の薬草店を共通の店舗データに移し、装備の3D表示とメニューを拡張 |
| G 検査 | アセット上限・骨格・ハッシュ、従来のセーブ、Node・Chromium・WebKitのテスト | 実機iPhoneの操作確認と長時間の描画・発熱計測 |
| H 公開 | 安全な追加カタログPRのゲート、Actionsの公開処理、Workの公開経路 | GitHub標準auto-mergeや保護を使う運用に切り替える際は、管理者権限と必須チェックを確認 |
| I Meshy | 既存タスクのGETと取得、有料承認ID・上限・再送防止 | 追加の有料操作が必要な依頼で、価格を確認して個別承認を取る |

## 続きから進める

1. [運用手順](RPG_AUTOMATION.md) を読み、`assets/rpg/catalog.json` の `mina` と `watchpost-round` で実運用例の登録状況を確認する。未登録なら [依頼例](requests/watchpost.json) をカタログに適用する。
2. `Game checks` とPagesを確認する。実運用例の合格条件は、ミナとの会話、見張り台への訪問、報酬、三連撃・同行の解放、セーブからの復帰。
3. 次の依頼では同じカタログを使う。新しい仕組みが必要ならコードPRで追加し、ゲームデータの追加PRと切り分ける。無料の調査や実装は、有料の承認待ちでも進める。
