# Meshy AIなどのGLBを追加する

ゲームのプログラムを変更せず、`manifest.json`で設定できます。ファイル名の大文字・小文字は区別されます。

現在はアニメーション付き `hero_animated.glb` を使用しています。クリップ名・剣・接地の設定は [ANIMATIONS.md](ANIMATIONS.md) を参照してください。以前の静的な `hero.glb` と `hero-mobile.glb` も保持しており、記録は [HERO.md](HERO.md) にあります。

## 主人公を差し替える

1. Meshyから**テクスチャを埋め込んだGLB**をダウンロードします。
2. `hero.glb`としてこのフォルダにアップロードします。
3. `manifest.json`を次のように編集します。新しい `hero.glb` をアップロードした場合は、`player.url` を `./hero.glb` に変更してください（既定はアニメーション付きモデルです）。

```json
{
  "player": {
    "url": "./hero.glb",
    "height": 1.9,
    "rotationY": 0,
    "animations": {
      "idle": "Idle",
      "walk": "Walking",
      "run": "Running",
      "jump": "Jump",
      "attack": "Attack",
      "dodge": "Dodge"
    }
  },
  "objects": []
}
```

- `height`：ゲーム内での身長（メートル）。足元を地面に合わせ、中央に配置します。
- 標準では**+Zが正面、+Yが上**です。逆向きなら`rotationY`を`3.141593`にします。角度はラジアンです。
- アニメーション名はGLBの実際のクリップ名に合わせます。アニメーションがなくても移動・ジャンプは機能します（モデルはポーズ固定）。
- 主人公の衝突半径はゲーム側の0.38mです。GLBの細かな形状から衝突形状を自動生成しません。
- 簡易キャラクターへ戻すには`"player": null`にします。

## モンスター・建物・街並みを配置する

```json
{
  "player": null,
  "objects": [
    {
      "url": "./house.glb",
      "height": 6,
      "x": 18,
      "z": -14,
      "rotationY": 1.570796,
      "colliderRadius": 2.5
    },
    {
      "url": "./monster.glb",
      "height": 1.5,
      "x": 12,
      "z": -8,
      "yOffset": 0,
      "colliderRadius": 0.5
    }
  ]
}
```

`x, z`は平面上の位置です。原点付近がはじまりの小径で、主人公の初期位置は`x:0, z:12`、北が`-Z`、東が`+X`です。地面の高さに自動配置します。`yOffset`で上下を微調整できます。

`colliderRadius`を省略すると通り抜けられます。指定するとモデル中心の円形障害物になります。建物の中や階段を歩けるメッシュ衝突ではありません。街並みは建物を分割して配置すると、通路を確保しやすくなります。`objects` に置いたモンスターは背景オブジェクトです。戦闘可能な敵の見た目を変える場合は、以下の `monsters` 設定を使います。

## iPhone向けの目安

- 最初は1モデル5,000〜15,000三角形程度、テクスチャは512〜1024px、GLBは数MB以内で試してください。端末と画面内の総量で負荷が変わります。
- 主人公、モンスター1体、建物1棟の順に追加して実機で確認します。
- Draco / Meshopt / KTX2などの追加デコーダーが必要な圧縮は、このバージョンでは未対応です。標準GLB、PNG / JPEGの埋め込みテクスチャを使ってください。
- モデルにはアプリから参照可能なファイルだけを指定します。推奨はこのリポジトリ内への配置です。外部URLはCORSやネットワークによって失敗します。
- GLBやテクスチャの利用条件を確認してから公開してください。

読み込みに失敗した主人公は簡易モデルへ戻り、失敗した配置物はスキップします。ブラウザの開発者コンソールに理由が表示されます。


## Ver.0.2：戦闘するスライム・ゴブリンを差し替える

`slime.glb` / `goblin.glb` をこのフォルダへアップロードし、`manifest.json` を次のようにします。

```json
{
  "player": null,
  "objects": [],
  "monsters": {
    "slime": {
      "url": "./slime.glb",
      "height": 1.0,
      "rotationY": 0,
      "animations": {"idle": "Idle", "walk": "Walk", "attack": "Attack", "death": "Death"}
    },
    "goblin": {
      "url": "./goblin.glb",
      "height": 1.8,
      "rotationY": 0,
      "animations": {"idle": "Idle", "walk": "Walk", "attack": "Attack", "death": "Death"}
    }
  }
}
```

- その種類の敵全体を差し替えます。配置・HP・攻撃力・AI・経験値・当たり判定はゲーム側が管理します。
- 正面は+Z、上は+Y。`rotationY` はラジアンです。
- アニメーションがなくても移動・攻撃・死亡処理は動きます。死亡クリップがない場合は縮小して倒れる表示になります。
- スキン付きGLBはSkeletonUtilsで個体ごとに複製します。ジオメトリとマテリアルは共有し、アニメーション状態は個別です。
- GLBは簡易モデルと異なり描画が自動でインスタンシングされません。同時に8体を表示するため、最初は1体5,000三角形程度、テクスチャ512px程度から試してください。
- 一方のモデルだけ失敗した場合も、その種類は簡易モデルで戦闘を継続します。`null` に戻すと簡易モデルになります。
- 攻撃・死亡アニメーションの見た目が変わっても、ダメージの発生時刻はゲーム側の判定が基準です。
